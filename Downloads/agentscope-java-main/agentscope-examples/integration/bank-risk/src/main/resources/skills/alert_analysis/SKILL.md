# 商业银行客户预警分析框架

## 一、预警分类体系

本行预警系统覆盖以下预警类别，每类预警反映不同维度的风险信号：

| 类别 | 覆盖范围 | 典型预警信号 |
|------|----------|-------------|
| 信用类 | 客户偿债能力和信用状况 | 多头授信、借新还旧、逾期欠息、应收账款异常、经营现金流恶化、关联交易 |
| 合规类 | 客户法律合规和监管风险 | 环保处罚、税务违法、反洗钱、海外制裁合规、信息披露违规、诉讼仲裁 |
| 操作类 | 客户经营和运营风险 | 安全事故、供应链中断、核心客户流失、产能异常、IT系统故障 |
| 声誉类 | 客户声誉和舆情风险 | 媒体负面报道、社交媒体发酵、评级下调、监管通报批评 |

## 二、预警分析方法论

### 2.1 分析原则

- **逐条独立分析**：每条预警独立判断风险程度，不提前合成
- **多维度评估**：每条预警从以下五个维度评估
- **交叉研判**：所有预警分析完毕后，跨类别交叉研判综合风险

### 2.2 五维度分析法

对每条预警，从以下五个维度逐一评估：

| 维度 | 评估内容 | 分析要点 |
|------|----------|----------|
| 等级 | 预警等级（红/橙/蓝） | 红色=立即关注、橙色=重点跟踪、蓝色=常规关注 |
| 类别 | 预警归属类别 | 判断该类别内是否还有其他预警（同类集中=系统性风险） |
| 核查结果 | 核查结论的可信度和严重性 | 已核实/部分核实/待核实；核查是否确认了预警的有效性 |
| 时效性 | 距离当前的时间 | 近7天=紧急、7-30天=活跃、30-90天=跟踪、>90天=归档 |
| 关联性 | 与其他预警的关联 | 是否与同企业其他预警存在因果关系或叠加效应 |

### 2.3 逐条分析输出格式

每条预警输出：

```
预警名称：[名称]
预警类别：[类别] | 预警等级：[红/橙/蓝]
发布时间：[日期] | 距今：[N]天
核查情况：[已核实/部分核实/待核实]

▸ 等级评估：[红色=需立即响应 / 橙色=需重点跟踪 / 蓝色=常规关注]
▸ 核查评估：[核查结论概述 + 可信度判断]
▸ 时效评估：[紧急/活跃/跟踪/归档 — 依据距今时间]
▸ 关联评估：[与其他预警的交叉信号，如无可标注"独立信号"]
▸ 本条结论：[一句话概括该预警反映的核心风险]
```

## 三、综合研判规则

所有预警逐条分析完毕后，进行跨预警综合研判：

### 3.1 综合等级判定

采用"最差情形 + 类别交叉"原则：

| 条件 | 综合等级 |
|------|----------|
| 任一条为红色预警 | 综合不低于"红色关注" |
| 同一类别出现 3 条及以上预警（含至少 1 条红色） | 综合至少"红色关注"，标注该类别的系统性风险 |
| 跨 2 个类别出现橙色及以上预警 | 综合升至"橙色重点关注" |
| 仅有蓝色预警 | 综合为"蓝色常规关注" |

### 3.2 趋势研判

| 信号 | 研判 |
|------|------|
| 近 30 天内预警数量 ≥ 3 条 | 风险正在集中暴露，关注客户基本面是否恶化 |
| 预警等级随时间升级（蓝→橙→红） | 风险呈扩大趋势，需研判后续可能出现的预警 |
| 核查结果"待核实"的预警占比 > 30% | 信息不完整，建议优先完成核查再定级 |
| 预警覆盖 ≥ 3 个类别 | 多维度风险暴露，非单一领域的偶发问题 |

### 3.3 输出结构

```
## 预警综合研判

### 预警概览
[表格：N条预警，红色X条/橙色Y条/蓝色Z条，覆盖M个类别]

### 逐条分析
[按五维度对每条预警的详细分析]

### 风险交叉矩阵
[类别之间的关联关系表]

### 综合结论
- 综合预警等级：[等级]
- 核心风险点：[2-3句话]
- 建议管理行动：[按紧急程度排列]
```

## 四、管理行动建议

| 综合等级 | 行动要求 |
|----------|----------|
| 红色关注 | 24小时内上报风险主管；冻结新增授信；启动专项风险排查；每3个工作日汇报进展 |
| 橙色重点关注 | 3个工作日内联系客户核实预警成因；加密贷后检查频次；评估是否需要増信措施 |
| 橙色普通关注 | 纳入重点监测名单；按预警类别逐条制定跟踪计划；下次贷后检查中重点核实 |
| 蓝色常规关注 | 记录至客户风险档案；常规贷后管理中跟踪预警变化趋势 |
