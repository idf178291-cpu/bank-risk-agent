# 问题归并指南

## 任务

将多个来源文档中提取的相似或重复问题归并为统一描述，避免同一问题在不同文档中被重复计数。

## 归并规则

### 相似归并

当多个问题描述的是同一类问题在同一机构/部门发生时，归并为一条问题：

**归并示例：**

| 原始问题 | 归并后 |
|----------|--------|
| 贷后检查不到位 | 贷后管理薄弱 |
| 贷后管理不到位 | （同上） |
| 贷后执行不规范 | （同上） |
| 反洗钱客户识别不完整 | 反洗钱客户尽职调查不足 |
| 未按规定开展身份识别 | （同上） |
| KYC信息更新不及时 | （同上） |

### 不归并的情况

以下情况即使问题类型相同也不归并：
- 不同分支机构/部门发生的同类问题
- 不同时间发现的同类问题（间隔超过1年）
- 涉及不同业务条线的同类问题

## 归并操作步骤

1. 浏览所有问题的标题和描述
2. 按业务领域分组（信贷、运营、合规、安保、人事、财务等）
3. 在每个组内，识别描述相同/相似的问题
4. 为可归并的问题确定统一的标题和描述
5. 在归并后问题的 relatedIssueIds 中记录所有原始问题的 issueId

## 输出格式

```json
[
  {
    "issueId": "ISS-merged001",
    "title": "归并后的问题标题",
    "description": "综合描述该问题的表现形式和影响范围",
    "relatedIssueIds": ["ISS-orig001", "ISS-orig002"],
    "mergeCount": 3,
    "sourceFiles": ["审计报告.docx", "整改台账.xlsx"]
  }
]
```

## 质量要求

- 归并后不允许存在完全重复的问题
- 每个归并后问题的 relatedIssueIds 不能为空
- 归并后问题总数应≤原始问题总数
