# 风险主题识别指南

## 任务

从已分类的风险问题中识别重点风险主题。一个风险主题是一组密切相关的问题集合，代表一个需要优先关注的风险领域。

## 评价维度

对每个识别的风险主题，从以下维度评分：

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 问题数量 (count) | 25% | >=5条→10分, >=3条→7分, >=1条→3分 |
| 未整改数量 (unresolved) | 25% | 全部未改→10分, 过半数→7分, 少数→3分 |
| 重复发生 (repeat) | 20% | 3次以上→10分, 2次→6分, 1次→2分 |
| 影响范围 (impact) | 15% | 全行→10分, 多支行→7分, 单支行→3分 |
| 风险等级 (severity) | 15% | 平均CRITICAL→10分, HIGH→7分, WATCH→3分 |

## 主题归纳示例

**输入问题：**
- 信贷审批权责不清
- 支行行长超权限审批贷款
- 部分贷款审批材料不完整
- 授信额度计算依据不充分
- 关联企业授信未合并管理

**归纳主题：** "信贷审批流程缺陷" — 涵盖审批权限、材料完整性、授信计算三类问题。

## 输出格式

按风险评分从高到低输出 TOP N 主题：

```json
[
  {
    "themeName": "信贷审批流程缺陷",
    "description": "信贷审批环节存在权限不清、材料不完整、授信计算不规范等系统性问题",
    "issues": ["ISS-001", "ISS-003", "ISS-007"],
    "riskLevel": "HIGH",
    "primaryCategory": "CREDIT_RISK",
    "issueCount": 3,
    "unresolvedCount": 2,
    "repeatCount": 2,
    "impactScope": "多支行"
  }
]
```

## 主题合并规则

1. 同一业务条线（信贷/运营/合规等）的问题优先合并
2. 同一根本原因的问题必须合并
3. 每个主题至少包含2个问题
4. 主题名称应反映根本原因而非表象
