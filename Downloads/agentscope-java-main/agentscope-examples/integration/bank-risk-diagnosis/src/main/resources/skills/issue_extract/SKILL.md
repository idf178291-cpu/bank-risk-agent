# 风险问题提取指南

## 任务

从提供的文档内容中提取所有潜在的银行风险问题，每条问题必须有明确的文档依据。

## 识别关键词

扫描文档中的以下关键词模式以定位问题：
- 发现/发现问题/存在问题/主要问题
- 检查发现/检查意见/检查结论
- 审计发现/审计意见/审计建议
- 整改事项/待整改问题/未整改
- 处罚事项/行政处罚/监管措施
- 违规/不符合/不到位/未落实/薄弱
- 风险隐患/风险点/风险事件

## 提取要求

对每个识别到的问题，提取以下信息：

```json
{
  "title": "问题标题（20字以内，概括核心问题）",
  "description": "问题详细描述（包含具体事实、数据、涉及部门）",
  "sourceExcerpt": "文档中描述该问题的原文摘录（用于证据链）",
  "discoveredDate": "发现日期 YYYY-MM-DD",
  "initialRiskLevel": "CRITICAL/HIGH/WATCH/LOW",
  "rectificationStatus": "PENDING/IN_PROGRESS/RESOLVED/VERIFIED"
}
```

## 风险评估准则

- **CRITICAL (严重)**: 涉及资金安全、重大监管处罚、系统性风险
- **HIGH (高风险)**: 多次重复发生、涉及核心业务、存在明显损失
- **WATCH (关注)**: 首次发现、影响范围有限、有整改计划
- **LOW (低风险)**: 轻微不规范、已即时纠正、无实质影响

## 整改状态

每个问题必须标注整改状态：

| 状态 | 含义 | 判定条件 |
|------|------|----------|
| PENDING (待整改) | 问题已识别但尚未启动整改 | 无整改计划或整改方案未获批 |
| IN_PROGRESS (整改中) | 整改措施执行中 | 已有整改方案且正在执行 |
| RESOLVED (已整改) | 整改措施已完成 | 整改方案已全部执行完毕 |
| VERIFIED (已核销) | 整改效果已验证通过 | 经检查/审计确认问题已消除 |

## 提取原则

1. 仅提取与银行风险相关的内容
2. 每一条问题必须有明确的文档出处（sourceExcerpt）
3. 客观描述，不添加文档中不存在的信息
4. 注意表格数据中的异常指标（不良率、资本充足率等）
5. 区分问题描述和建议/整改措施，只提取问题本身

## 输出格式

输出必须是 JSON 数组：
```json
[
  {
    "title": "贷后管理不到位",
    "description": "2025年对公贷款贷后检查频率不达标，XX支行15笔贷款中8笔未按规定频次开展贷后检查",
    "sourceExcerpt": "检查发现，XX支行对公贷款贷后管理存在薄弱环节，15笔贷款中有8笔未按规定频次开展贷后检查工作",
    "discoveredDate": "2025-03-15",
    "initialRiskLevel": "HIGH",
    "rectificationStatus": "PENDING"
  }
]
```
